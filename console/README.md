# Firenook console

The emulator's own UI. A client-only React application, built with Vite and
embedded into the engine binary, served under `/console` on the Emulator UI
port. Every asset and API call is same-origin with the page, so the console
works whatever scheme or address the UI was opened with.

Status: every section is built, on one live connection per browser and a
kit every section is made from: the Overview, Firestore (data and rules),
Authentication, Storage (files and rules), Functions, Extensions, Eventarc,
Pub/Sub, Cloud Tasks and Logs, linked to each other wherever one names what
another shows. A section the engine does not run is behind its gate, which
says why and how to turn it on. The Google Emulator UI keeps answering at
`/` on the same port until every row of `support/console-parity.md` is
ticked.

## Working on it

```
npm ci --prefix console
npm run engine --prefix console -- --profile all     # a synthetic engine: every service, fixture and seeder
FIRENOOK_UI_ORIGIN=http://127.0.0.1:<ui port> npm run dev --prefix console   # Vite with HMR against it
npm run build --prefix console     # console/dist, read at runtime by debug engine builds, embedded by release builds
```

`npm run engine` prints the origin to give the dev server. Profiles are
`data`, `auth`, `storage`, `compute`, `messaging`, `observe` and `all`
(`scripts/profiles/`); `FIRENOOK_BINARY` points at the engine to run, and
`FIRENOOK_SEED_SCALE=large` asks the seeders for their perf datasets.

Checks, all run in CI:

```
npm run check --prefix console         # TypeScript
npm run lint --prefix console          # oxlint
npm run format:check --prefix console  # oxfmt
npm run test --prefix console          # Vitest + Testing Library, compiled by the React compiler as the build is
npm run budget --prefix console        # entry and landing-route gzip budgets from the Vite manifest
npm run e2e:sdk --prefix console       # once: the offline Functions SDK the fixture codebase links
npm run test:e2e --prefix console      # every Playwright project, each against real engines
cargo test -p firenook-console-front   # Console API tests; also writes src/api/generated/*.ts
```

One Playwright project per area (`data`, `auth`, `storage`, `compute`,
`messaging`, `observe`, `shell`): `npx playwright test --project data` from
`console/`. The shell project's perf journeys are opt-in:
`FIRENOOK_PERF=1 FIRENOOK_SEED_SCALE=large npx playwright test --project shell --grep @perf`.
They measure the grid, the live channel and background tabs on the Firestore
page, and FeedList and JsonView on the kit harness (`e2e/kit-harness/`), which
they build in production mode and serve beside the engine's console.

The component library: `npm run design-system --prefix console` renders every
card in `design-system/src/cards/` and captures it to `.design-system/`;
`npm run design-system:dev` serves the cards while you work on them.

## Layout

```
src/routes/                 file routes (routeTree.gen.ts is generated by the router plugin and committed)
src/<section>/              one folder per section: firestore/, auth/, storage/, functions/, extensions/,
                            eventarc/, pubsub/, tasks/, logs/, overview/
src/rules/                  the rules kit both rules pages are built on (Firestore's and Storage's)
src/compute/, messaging/,   code shared by the sections of one stream (Functions, Extensions and Eventarc;
  observe/                  Pub/Sub and Cloud Tasks; Logs and the Overview)
src/components/shell/       the app shell, navigation, top bar, palette, jobs watch
src/components/console/     the section kit: page, toolbar, table, feed, inspector, JSON, editors, requests, states
src/components/kit/         small pieces the shell itself uses (badges, dots, kbd)
src/components/code-editor/ CodeMirror behind a lazy import
src/lib/                    the live channel (live/), section registry (sections/), formats, identity, filter grammar, shortcuts
src/api/                    fetch client, query options, generated Console API types (never hand-edited)
e2e/                        Playwright journeys, their fixtures (fixtures.ts) and helpers (support/)
scripts/                    synthetic engine, profiles, fixtures, seeders, the Functions SDK, bundle budget, design-system capture
design-system/              the component library's cards
```

The Rust side is `crates/console-front`: the Console API, the live channel,
the embedded assets and their cache policy. Rust types are the contract;
ts-rs exports them into `src/api/generated`.
